## Changes and fixes

- **Content first:** Each Detailed screen opens with its main content. One Show all button reveals secondary controls; Show less returns to the summary.
- **Visible target caps:** Segment cards and person rows show their caps. Remaining pieces, finish dates and shared summaries use the effective percentage.
- **Segment overview:** Segment cards show a model count and model names directly. Search works in By segment and All models; tapping a model opens the shared editor.
- **Connected model names:** Saved names and Samsung references appear in the library. Editor changes update scanner names; bulk-imported names update the shared library too.
- **Database protection:** Read failures no longer look like an empty installation. Damaged scan rows show a warning and stay on disk. Save failures have a visible retry action.
- **Atomic writes:** Synchronous write errors now abort the transaction. Tests verify record writes, retail state and snapshots cannot partially commit.
- **Backup validation:** Missing retail state is rejected; empty, unreadable and invalid files have distinct messages. A later file selection cannot be overwritten by an older pending read.
- **Saved settings:** A low-stock threshold of zero survives reload. Damaged report template fields are cleaned before report generation.
- **Server connections:** Concurrent uploads are serialized per job: all six uploaded photos remain listed. Malformed JSON returns a client error. Authorization and path checks pass.
- **Shared reports:** Shared text opens Report on an empty app, and another share refreshes the report input when the app is already open.
- **Back navigation:** Popup removal and screen navigation now coordinate their history entries. Modern Android Back uses the page navigation depth; More closes before the screen changes.
- **Build consistency:** Android asset copying replaces old bundles with the exact current web build. The final APK was installed and its web bundle verified on the isolated emulator app.

## Limits and remaining work

- Database tests use a fresh synthetic browser profile. They do not inspect or certify the saved data on your own phone.
- Real-phone camera quality, WhatsApp delivery, Bluetooth reception, battery/thermal behaviour and cloud-hosted deployment still need device/service testing.
- The production dependency audit reports two moderate entries in the ExcelJS → uuid chain. No high or critical production advisory was reported. A breaking dependency downgrade was not applied.
- The build retains a large-JavaScript-chunk warning, and Gradle reports deprecated build APIs. These did not prevent the builds or listed checks from passing.
- This is a local debug-signed test build, package com.imeilens.scanner.phonetest, version 1.26.0-phonetest. The production app was not replaced. No commit, push, public deployment or release was made.
